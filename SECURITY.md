# Security policy

## Supported versions

The project is pre-1.0. Only the latest commit on the default branch receives security fixes.

## Reporting a vulnerability

Do not open a public issue containing exploit details, system evidence, or identifiers. Use GitHub's private vulnerability reporting feature when enabled, or contact the maintainer through the repository profile and request a private channel.

Include the affected version, impact, reproduction using synthetic data, and suggested mitigation. Never attach a real support bundle without independently removing personal data.

## Security boundary

SupportKit is read-only, local-first, rootless, offline-capable, and contains no automatic upload or telemetry. See `docs/THREAT_MODEL.md` for controls and residual risks.
